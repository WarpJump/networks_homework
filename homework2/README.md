# Простое сетевое приложение Клиент-Сервер на C++

Простенькое приложение для демонстрации сетевых протоколов на C++. Есть четыре режима работы: TCP сервер/клиент и UDP сервер/клиент
## Ключевые особенности

*   **Поддержка TCP и UDP**: Реализованы клиенты и серверы для обоих протоколов.
*   **Четыре режима работы**: Управляется через аргументы командной строки.
*   **Безопасное управление ресурсами (RAII)**: Класс `SocketRAII` гарантирует автоматическое закрытие сокетов при выходе из области видимости, предотвращая утечки файловых дескрипторов.
*   **Совместимость с `netcat`**: Протокол обмена данными прост и совместим со стандартной утилитой `netcat` как в режиме клиента, так и в режиме сервера.
*   **Обработка больших сообщений**: TCP-сервер корректно обрабатывает сообщения, размер которых превышает MTU (например, > 20 Кб), хотя текущая реализация `handle_tcp_client` использует упрощенную модель чтения (см. описание протокола).
*   **Переподключение клиентов**: После отключения одного клиента TCP-сервер продолжает работу и готов принять нового.

## Сборка
```bash
g++  main.cpp -o network_app
```

## Использование
Приложение управляется через аргументы командной строки в формате 

server: `./network_app server <tcp|udp> <port>`

client: `./network_app client <tcp|udp> <host> <port>`.


## Описание протокола взаимодействия


### Протокол TCP

*   **Тип**: Текстовый, потоковый.
*   **Формат сообщения**: Сообщения представляют собой строки текста. Разделителем сообщений является символ новой строки (`\n`).
*   **Взаимодействие**: Приложение работает в режиме пошагового чата. Одна сторона отправляет сообщение, завершающееся `\n`. Другая сторона получает его, выводит на экран, а затем отправляет свой ответ.
*   **Обработка больших сообщений**: Текущая реализация в `handle_tcp_client` читает данные одним вызовом `recv()`. Для прохождения теста на >MTU это работает, так как TCP-стек ОС собирает пакеты в буфер, и `recv` с большим буфером, скорее всего, прочитает всё сообщение. Более надежная реализация накапливала бы данные в цикле до обнаружения символа `\n`. Клиентская часть также работает по этому принципу.

### Протокол UDP

*   **Тип**: Дейтаграммный. Каждое сообщение — это одна независимая дейтаграмма.
*   **Взаимодействие**:
    1.  Клиент отправляет дейтаграмму с сообщением на сервер.
    2.  Сервер получает дейтаграмму, выводит её содержимое и адрес отправителя.
    3.  Сервер отправляет обратно клиенту подтверждающую дейтаграмму с фиксированным текстом "Message received".
    **Замечание**:
        Сервер по своему собственному желанию не может отправить произвольный пакет к клиенту

## Структура исходного кода

**`main()`**: Разбирает аргументы командной строки и запускает нужный режим работы.
**`SocketRAII`**: RAII-обертка над файловым дескриптором
**`setup_server_socket()` / `setup_client_socket()`**: Создают, настраивают и привязывают сокет
**`run_tcp_server()` / `run_tcp_client()`**: Основную логика TCP.
**`handle_tcp_client()`**: Обрабатывает сессию одного TCP-клиента.
**`run_udp_server()` / `run_udp_client()`**: Основная логика для UDP.
